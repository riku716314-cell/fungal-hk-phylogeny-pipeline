## 2. HK 候補のスクリーニング

### 2.1 使用した Pfam プロファイル

| ドメイン | Pfam ID | 役割 |
|---|---|---|
| HisKA | PF00512 | ヒスチジンキナーゼの二量体化・リン酸受容部位 |
| HATPase_c | PF02518 | ATP 結合部位 |
| REC | PF00072 | レシーバードメイン (ハイブリッド型 HK が持つ) |

```console
$ hmmpress Pfam-A.hmm
$ hmmsearch --tblout HisKA.tblout HisKA.hmm proteome.fasta
```

### 2.2 2/3 ドメインルール

E-value ≤ 1e-5 でフィルタし、上記 3 ドメインのうち **2 つ以上**を持つ配列を
HK 候補としました。Mina et al. (2024) の基準に準拠しています。

**この基準を選んだ理由**: 3 ドメイン全てを必須にすると、REC を持たない
非ハイブリッド型 HK を取りこぼします。逆に 1 ドメインでは他のシグナル伝達因子が
大量に混入します。2/3 はその折衷点です。

## 3. 入力データの検証

**この工程は省略できません。** 系統解析ツールは配列の生物学的な妥当性を
検証しないため、破損したデータでも正常に完走します。

### 3.1 実際に発生した事故

データセットから一部の配列を除外する際、`>` で始まるヘッダ行のみを削除する
処理を行ったことがありました。配列本体の行が残り、直前の配列の末尾に連結され、
本来 1220 aa の配列が **7920 aa** になっていました。

**アライメント・系統樹推定ともに警告なく完走**し、それらしい系統樹が出力されました。

### 3.2 対策

FASTA のパースは、必ずヘッダ単位で状態を持って行います。

```python
for line in f:
    if line.startswith(">"):
        if header is not None:
            seqs[header] = "".join(buf)   # 直前の配列を確定させてから
        header, buf = line[1:].split()[0], []
    else:
        buf.append(line.strip())
```

そのうえで `validate_fasta.py` により以下を検査します。

1. 重複ヘッダ
2. 空配列
3. 配列長の外れ値 (中央値の 3 倍を超えるもの)
4. アミノ酸として不正な文字
5. **NCBI に問い合わせた配列長との照合** (`--verify-ncbi`)

**5 が決定的でした。** 上記の事故を再現した検証では、連結により 1994 aa が
3195 aa になったケースを 3 の統計的検査では検出できず (中央値の 3 倍未満のため)、
NCBI 照合によって初めて捕捉できました。

## 4. アライメントとトリミング

```console
$ mafft --auto merged.fasta > aligned.fasta
$ trimal -in aligned.fasta -out trimmed.fasta -gt 0.2
```

### trimAl のパラメータ選択について

当初は `-automated1` を使用しましたが、**1 配列が削除されました**。

```
Removing sequence 'XXXXXXXX' composed only by gaps
```

全長にわたってギャップが多い配列が、トリミング後に全ギャップとなり
除去されたものです。解析対象の配列が失われるのは許容できないため、
ギャップ率による固定閾値 `-gt 0.2` (各列で 20% 以上の配列が
アミノ酸を持つ列のみ残す) に変更し、全配列を保持しました。

**トレードオフ**: `-gt 0.2` は `-automated1` より保守的なトリミングであり、
情報量の少ない列が残る可能性があります。配列を失うリスクとの比較で
前者を選んでいます。

## 5. 系統樹推定

```console
$ iqtree -s trimmed.fasta -m LG+G4 -bb 1000 -nt AUTO -o EcoliEnvZ
```

| オプション | 意味 |
|---|---|
| `-m LG+G4` | LG 置換行列 + 離散ガンマ分布 4 カテゴリ |
| `-bb 1000` | UFBoot によるブートストラップ 1000 回 |
| `-nt AUTO` | スレッド数の自動決定 |
| `-o EcoliEnvZ` | **外群の指定** |

### 外群を指定する理由

`-o` を指定しないと無根樹が出力されます。無根樹でも系統関係は読めますが、
**分岐の順序 (どちらが祖先的か) を議論できません**。
大腸菌 EnvZ は真菌 HK に対する外群として確立しており、これを指定することで
真菌 HK 全体の根の位置が定まります。

## 6. グループ分類の割り当て

### 6.1 アンカー配列の確定

グループ分類は、先行研究で分類が確定した配列 (アンカー) を基準に行います。

アンカーの同定では、**配列のタイトルではなく locus_tag で照合**しました。
NCBI 上の自動命名 (`hypothetical protein`、あるいは機能を推定した通称) は
論文の遺伝子名と一致しないことが多く、タイトルだけを見て「別遺伝子である」と
判断するのは誤りの元です。

実際、本パイプラインの構築中に配列タイトルから「先行研究の遺伝子とは
別物ではないか」と誤った判断を一度しています。E-utilities で locus_tag を
取得して論文の Table と照合したところ、10 件すべてが 1 対 1 で対応しました。

```console
$ python scripts/fetch_ncbi_sequences.py \
      --acc-list accessions.txt --metadata --out metadata.tsv
```

### 6.2 グループ伝播アルゴリズム

各アンカーについて、それを含むクレードを根の方向へ拡張し、
**別グループのアンカーが混入する直前**で停止します。得られたクレードの
葉すべてにそのアンカーのグループを与えます。

- 同一グループの複数アンカーは衝突とみなしません。1 種が同一グループに
  複数のパラログを持つ場合、それらが同じクレードに入るのは正常なためです
- どのクレードにも入らなかった配列は、最近縁アンカーへの patristic distance
  による **`fallback` 判定**とし、確度が低いことを出力に明示します

### 6.3 外群の扱い

**外群はグループ判定から明示的に除外します。**

当初この処理が無く、外群である大腸菌 EnvZ が Group I と判定される誤りが
生じました。外群はグループ分類の枠組みの外にある配列であり、
どのグループにも属さないのが正しい扱いです。

```python
def leaves_of(clade):
    return {t.name for t in clade.get_terminals() if t.name != outgroup}
```

> **記録として**: この修正で変更したのは**ラベル付けのロジックのみ**であり、
> 系統樹そのものには一切手を加えていません。結果を都合よく書き換えたのでは
> ないことを明確にするため、修正の内容と理由をここに残します。

### 6.4 自己検証

`assign_groups.py` は実行のたびに、**アンカー配列自身が期待どおりの
グループに再現されるか**を検査し、1 件でも不一致があれば異常終了します。

104 配列の系統樹での検証では、先行研究で分類が確定している 10 配列
すべてを再現しました。

## 7. ドメイン構成の判定

### 7.1 HMMER と SMART の使い分け

| 段階 | ツール | 目的 |
|---|---|---|
| 一次スクリーニング | HMMER (Pfam-A) | 大量の配列から HK 候補を絞る |
| 最終判定 | SMART | 先行研究と同一基準でドメイン構成を確定 |

同じ配列でも両者で検出結果が一致しないことがあります。どちらかが誤りという
より、プロファイルと閾値の設計が異なるためです。

**この差は既知データで確認しました。** 分類が確定している種の配列に対しても
HMMER の結果は文献の記載と一致しませんでした。つまり差の原因は解析対象の
データではなくツール間の違いであり、SMART の結果は文献の基準と一致しました。

したがって、**先行研究と比較する際は、その研究が使用したツールに揃える**
必要があります。

### 7.2 SMART の結果の扱い

SMART の出力には `STATUS=hidden|threshold` の候補が多数含まれます。
これらは閾値に達していない予測なので、**`visible` のもののみ**を採用します。

## 8. 既知の限界

- **グループ判定はアンカーの正しさに完全に依存します。** アンカーの分類が
  誤っていれば、伝播先もすべて誤ります。アンカーは査読済み文献から取ること
- **`fallback` 判定は推定です。** 距離ベースであり、クレード判定より確度が劣ります
- **ブートストラップ値の低いノードでは、クレードの境界自体が信頼できません。**
  判定結果は必ず支持率と併せて解釈してください
- **`-gt 0.2` は保守的なトリミングです。** 情報量の少ない列が残っている可能性があります
- **NCBI 照合の対象はアクセッション番号形式のヘッダのみです。** 独自 ID を
  付けた配列は照合できません
- **単一遺伝子系統樹の限界**: 本パイプラインは HK ファミリー単独の系統樹を
  扱います。種の系統関係とは一致しない場合があります
